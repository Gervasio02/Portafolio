Proyectos

Cinco aplicaciones, cada una con un problema concreto. Las demos usan datos ficticios y funcionan en tu navegador.

01 Gestión de trabajo

TaskFlow

Un tablero Kanban para equipos que preparan entregas y atienden incidentes, con un panel que muestra qué se está atrasando.

El problema
Saber quién puede editar qué tablero, y que el orden de las tarjetas no se rompa cuando dos personas las mueven a la vez.
Lo que más me costó
Mantener las posiciones consistentes con transacciones en PostgreSQL y probar los permisos de dueño, editor y lector.

React · Express · Prisma · PostgreSQL

02 Reservas

ReservaYa

Reserva de canchas deportivas con tarifas por horario, comprobante y cancelación.

El problema
Que nunca se asigne el mismo turno a dos personas, aunque las dos confirmen en el mismo segundo.
Lo que más me costó
La concurrencia entre reservas y bloqueos de mantenimiento, y manejar bien las fechas en la zona horaria de Santiago.

React · FastAPI · SQLAlchemy · PostgreSQL

03 Comercio electrónico

TiendaNova

Una tienda con catálogo, variantes, cupones, pedidos, devoluciones y panel de administración. Los pagos son simulados.

Cómo trabajo

Cuatro hábitos que intento mantener en todos los proyectos.

  1. Las reglas viven en el servidor

    La interfaz puede ocultar un botón, pero es la API la que decide si tienes permiso. Nunca al revés.

  2. La base de datos tiene la última palabra

    Restricciones únicas y transacciones en PostgreSQL, en vez de confiar en que dos peticiones nunca lleguen juntas.

  3. Probar contra una base real

    Las pruebas de API usan PostgreSQL de verdad, no un simulacro. Así aparecen los errores que de otro modo verías en producción.

  4. Cada cambio pasa por CI

    GitHub Actions prueba cada push. Si todo pasa, la app se despliega sola en Azure, y si falla, sigue la versión anterior.
